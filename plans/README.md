## Audit-vs-code corrections the plan-writing pass caught

The plan agents re-opened every cited file; three findings needed adjustment (the plans reflect the
corrected reality, not the original audit framing):

- **Plan 011 (recomposition)** — the audit's PERF-01 claimed both `decryptedFiles` *and*
  `downloadingFiles` need per-row slicing. At `45e2832e`, `decryptedFiles` is **already an
  `ImmutableMap` end-to-end** (UiState/MessageItem/MediaItem) — partial false positive. The genuinely
  unstable prop is `downloadingFiles` (bare `Set<String>`). Plan 011 is scoped to that + the three
  other (confirmed) recomposition fixes; full per-row slicing of the whole-map identity churn is
  documented as a deferred follow-up (it would require re-plumbing the bubble signature tree).
- **Plan 010 (dead code)** — `editFile`/`openAppStore` are **interface methods** on
  `FileSystemHandler` (overridden as `TODO()`), not `expect` funs as the finding said; `keyboardHeightAsState`
  is an `expect` fun whose non-iOS actuals are real-but-unused. All three verified **zero-caller**, so
  removal is still safe. Minor line drift (right members).
- **Plan 025 (LoginViewModel test)** — the audit assumed a fakeable auth-client interface and a
  one-time-event SharedFlow. Reality: collaborators are **concrete final classes** (no interface, no
  Mockito/MockK), `init {}` touches the `SecureStorage` global, so a real `LoginViewModel` **cannot be
  constructed in a unit test without a testability refactor** (out of scope). And `LoginUiEvent` is
  stored in `LoginUiState.uiEvent`, **not** a SharedFlow (so it's also a Plan-014 convention violator).
  Plan 025 is rescoped to test the isolatable pure logic (id-validity gate, ping 200/non-200/throw via
  Ktor `MockEngine`, `observeAuthState` terminal-vs-loading) with zero source changes, and flags the
  full VM-under-test as the higher-value follow-up *if* the collaborators are ever refactored to interfaces.

## Findings considered and rejected / deferred (so they aren't re-audited)

These were surfaced by the audit but deliberately **not** turned into plans:

- **WS reconnect jitter has no floor** (`OdinWebSocketClient.kt` `withJitter`): dormant — base delay
  is 1s and the 20% negative jitter is harmless today. LOW confidence. Not worth a plan; revisit only
  if the base delay is ever lowered.
- **`isStrongKey` defined but never enforced** (`ByteArrayUtil.kt:231`): folded into **plan 001**'s
  maintenance note (it pairs with the RNG fix); not a standalone plan.
- **Dead version-catalog entries** (`com.android.support.*` runner/espresso/appcompat-v7,
  `accompanist-systemuicontroller`, zero references): a trivial 5-minute cleanup — delete the
  orphan `[versions]`/`[libraries]` entries from `gradle/libs.versions.toml`. Not given its own plan;
  do it opportunistically alongside plan 008 (both touch the catalog).
- **`homebase-common` ships under the `id.homebase.core.*` package** (401 files): a real smell with L
  effort that churns every import — **needs a maintainer decision** before any rename. Recommended path
  is *not* a mass rename but a Konsist rule that new `homebase-common` files use `id.homebase.common.*`
  so the divergence stops growing. Deferred pending that decision.
- **`desktopApp` excludes `homebase-chat` from `homebase-core` then re-adds it per-OS** (the
  "new chat dep → NoClassDefFoundError on Desktop only" footgun, already in CLAUDE.md): fixing the root
  cause needs the native-binary/ABI fan-out understood; the lightweight mitigation is a Gradle
  verification task that fails the Desktop build when a chat runtime dep is missing from core. Deferred.
- **Secondary chat correctness niceties** — edit-path error masking + false-failure-after-enqueue,
  `handleEditMessageSave` wedging the composer on "Sending", forward-to-new-contacts with no rollback:
  real but MED confidence / lower leverage; outside the four selected bundles. Worth a future pass.
- **Secondary API correctness niceties** — ping-supervisor stale fallback loop on reconnect, outbox
  missed-wakeup when a dependency drains, DriveSync transient-error detection by class-name
  string-matching: real but LOW–MED confidence / lower leverage; outside the selected bundles.
- **Half-built Moments save/delete** (`MomentDetailScreen.kt` `onSave`/`onDelete` no-op lambdas): a
  feature-completion task, not a quality/parity fix; outside the selected bundles. Either hide the
  controls or wire them to the moments action service.
